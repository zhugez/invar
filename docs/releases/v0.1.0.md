# Invar v0.1.0

**Change code. Preserve behavior.**

Invar is a local CLI that captures command results, requires explicit approval, and compares later runs with accepted examples. It complements existing tests.

## Download and install

The prebuilt archive is for **Linux x86_64, including Linux under WSL**. It contains a statically linked musl executable. Rust and Python are not required to run Invar. Your configured commands still need their own runtimes.

Install with one command:

```sh
curl -fsSL https://github.com/zhugez/invar/raw/main/install.sh | sh
```

The installer pins this release's archive SHA-256. It retains the full package under `${XDG_DATA_HOME:-$HOME/.local/share}/invar/0.1.0` and creates `~/.local/bin/invar` as a symlink to the executable. It does not invoke sudo or overwrite an executable from another installation. If the binary directory is absent from PATH, it updates `.bashrc` for Bash, `${ZDOTDIR:-$HOME}/.zshrc` for Zsh, or `.profile` for a POSIX shell. Open a new terminal after a PATH change. Other shells receive an instruction to add the directory themselves.

The command executes the repository's installer as your user. The release also includes `install.sh` as a separate asset. Neither the script nor its checksum establishes independent authentication.

### Manual download

Download `invar-v0.1.0-x86_64-unknown-linux-musl.tar.gz` and `SHA256SUMS` from this release. With `curl`, `sha256sum`, and `tar` installed:

```sh
set -eu
mkdir -p invar-v0.1.0-download
cd invar-v0.1.0-download
curl -fLO https://github.com/zhugez/invar/releases/download/v0.1.0/invar-v0.1.0-x86_64-unknown-linux-musl.tar.gz
curl -fLO https://github.com/zhugez/invar/releases/download/v0.1.0/SHA256SUMS
sha256sum -c SHA256SUMS
tar -xzf invar-v0.1.0-x86_64-unknown-linux-musl.tar.gz
./invar-v0.1.0-x86_64-unknown-linux-musl/invar --version
```

Expected version: `invar 0.1.0`. You can invoke this executable by its absolute path. To put it on your current shell's PATH:

```sh
export PATH="$PWD/invar-v0.1.0-x86_64-unknown-linux-musl:$PATH"
invar --help
```

This archive retains its licenses beside the executable. Check `command -v invar` if another tool already uses the name. Add the absolute directory to your shell configuration if you want to retain the PATH change across sessions.

SHA-256 checks detect corrupted or mismatched files. The checksum file is distributed through the same GitHub account as the binary. It is not a signature or independent authentication.

## Use it

In your project, run `invar init`, then edit `invar.json` to name explicit command arguments. Run `invar capture`, inspect `.invar/candidate.json`, and approve only the reviewed file with `invar lock --candidate SHA256_FROM_CAPTURE`. Run `invar verify` after code changes. Use `invar --json verify` for a versioned JSON report.

Do not automatically capture and lock new expectations after every code change. That would approve the behavior you are trying to check. See the source README for candidate inspection and a complete workflow.

Exit codes: `0` pass, `1` regression, `2` configuration/execution error, `3` missing or invalid baseline/candidate identity.

## Included in this release

- `init`, `capture`, explicit hash-pinned `lock`, and read-only `verify`.
- Exact comparison of exit codes and stdout/stderr bytes, including binary output.
- Versioned JSON reports, byte-difference diagnostics, bounded capture, deadlines, and ordinary Unix process-group cleanup.
- The executable, Apache-2.0 project license, dependency notices, Rust standard-library notices, musl notices, Cargo.lock, and `BUILD-INFO.json` recording the source commit, target, compiler, and binary/lockfile hashes.

## Verification and limits

The Linux musl release-profile suite passed all 19 tests. Warnings-denied Clippy passed for this target. ELF inspection found no interpreter or needed shared libraries. The ordering and isolated Rust fault-injection demonstrations exercise regression detection and repair.

Runtime evidence is from x86_64 Linux under WSL2. Native macOS execution remains unverified and this release has no macOS binary. Windows is unsupported. No dependency advisory scan or signed/reproducible-build claim is made.

Commands retain the invoking user's filesystem and network access. Local accepted files remain writable by sufficiently privileged users. Exact examples do not prove general correctness. Read `SECURITY.md` in the source before running commands from a project you do not trust.
